# フェンナ語例文チェックスキル


`document/ja/fennese/` 以下の原稿にある例文について、**語彙レベルの**整合性を確認する。

## 判定するもの・しないもの
| 判定可否 | |
| --- | --- |
| 判定する | フェンナ語文の中に辞書にない単語がないか |
| 判定する | 辞書の訳語から見て、フェンナ語文と日本語訳文の内容が語のレベルで食い違っていないか |
| **判定しない** | 文法 (語順・格・活用の正しさ・一致など), 判断が難しいので手を出さない |
| **判定しない** | 辞書で引けなかった語形が正しくは何か, 後述の通り推測しない |

## 推測の禁止
このスキルでは、**偽陽性を許容する**が、**偽陰性を避ける**方針をとる。
もっともらしい推測ができたとしても、**ユーザーから推測するよう指示されていない限り推測しない**。

具体的には、次のことを**してはならない**。
- 辞書で引けなかった語形について、「これは○○の屈折形だろう」と当たりを付けて問題なしと判断すること。
- 辞書で引けなかった語形について、「正しくは○○ではないか」と修正案を出すこと。
- 屈折データを持つ**別の語**の活用表から語尾のパターンを外挿して、引けなかった語形の妥当性を判断すること。
- 「これは誤検出である」というカテゴリを設けて、引けなかった語を報告から除外すること。

とくに、辞書には**屈折形データを持たない語がある** (借用語 `origin: "loan"` など)。
これらの語の屈折形は `lookup.ts` では原理的に引けないので、「引けない＝誤り」でも「引けない＝正しい」でもない。
**判断できないものは判断せず、引けなかったという事実だけを報告する**こと。
ユーザーがそれを見て、綴りの誤りなのか単に辞書側にデータが無いだけなのかを決める。

## Step 1: 対象範囲を決める
ユーザーの指示に従う (「`grammar/21.zml` の例文」「人称代体言の節」「さっき追加した分」など)。
範囲がはっきりしないときは、勝手に全体を走らせず、対象を確認すること。
例文は全体で 200 文以上あり、まとめて流すと出力が膨大になる。

スクリプトが取れる範囲はファイル全体か行範囲だけ。
「この節だけ」のようにファイルの一部を見たいときは、**まず自分で該当ファイルを読んで対象の行範囲を決め**、それを `--lines` に渡すこと。

## Step 2: 例文を抜き出す
```bash
npx tsx .claude/skills/verify-fennese/scripts/extract.ts <パス> [--lines A-B] [--format text]
```

- `<パス>` は `.zml` ファイルでもディレクトリでも良い (ディレクトリなら再帰的に `*.zml` を探す)。
- `--lines A-B` は `\xl` と `\xol` の開始行で絞り込む。節単位で見たいときに使う。
- `--format text` は人が読む用。既定の `json` はそのまま次の手順に渡す用。
- `\sh` に `mark` 属性が付いた例文 (意図的な非文・不自然文) は抽出されない。

出力される各文のフィールド:
| フィールド | 意味 |
| --- | --- |
| `id` | 通し番号 (報告のときに使う) |
| `filePath` | 原稿ファイル |
| `fennese` | フェンナ語文 |
| `japanese` | 日本語訳文。`null` なら訳文がないので内容の照合はできない |

## Step 3: 各語を辞書で引く
`extract.ts` の JSON をそのまま `gloss.ts` に渡す。
```bash
npx tsx .claude/skills/verify-fennese/scripts/extract.ts <パス> | npx tsx .claude/skills/verify-fennese/scripts/gloss.ts
```

内部で `~/.claude/skills/fennese-dictionary/scripts/lookup.ts` を呼び、各語の見出し語・品詞・訳語・活用情報を 1 行にまとめて出す。
末尾に「辞書にない語」の一覧が付く。

- `--no-inflection` — 活用情報を省いて出力を短くする。語彙の照合だけなら基本的にこれで足りる。
- `--format json` — 構造化された結果が欲しいとき。

次の語は辞書を引かずスキップされる (辞書にないのが当然のため)。
- 固有名詞マーク `‵` の付いた語 (`‵феши̂хто` など)
- 数字を含む語 (`\sbr` による数詞の略記など) (12 進法の `↊`, `↋` も数字扱い)
- ラテン文字だけから成る語 (単位の `kg` など)

一方、キリル文字にラテン文字が混ざった語はスキップされず、辞書を引いた上で「辞書にない語」として出る。
キリル文字とラテン文字の取り違えという綴りの入力ミスを拾うためなので、この形で報告されたときは綴りを疑うこと。

## Step 4: 判定する
出力を読んで、次のどちらかに当てはまる例文を拾う。
この 2 つ以外の観点は持ち込まない。

### 辞書にない語形がある場合
`✗ 辞書になし` と出た語をそのまま拾う。

`gloss.ts` の結果が唯一の根拠であり、これを覆すために追加の調査や推測をしない。
「未登録なのか」「綴りの誤りなのか」「屈折データが無いだけなのか」の切り分けはユーザーに委ねる。

ただし、辞書になかった綴りにキリル文字とラテン文字が混在していた場合は、明らかな入力ミスであるため、「ラテン文字混在による綴りのミス」と判断して良い。
この場合は、後述の報告の際に、ラテン文字が混ざっている旨を伝える。

辞書は日々更新されており、fennese-dictionary スキルに同梱の辞書はそのスナップショットである。
スナップショット日以降に追加された語は引けないので、報告の末尾にこの可能性を 1 行添えて良い (語ごとに個別の言い訳を付けるのではなく全体に対する注記として 1 回だけ)。

### フェンナ語文と日本語訳文の内容が語のレベルで食い違っている場合
日本語訳文の内容語 (名詞・動詞・形容詞など) を並べ、それぞれに対応する語がフェンナ語文の側にあるかを見る。
逆に、フェンナ語文にあるのに訳文のどこにも現れていない内容語がないかも見る。

例: 訳文に「花」とあるのに、フェンナ語文のどの語の訳語にも「花」に当たるものがない → 報告する。

**報告しなくて良いもの** (誤検出になりやすい):
- 意訳・省略。日本語として自然にするために語が足されたり消えたりするのは普通。
- 機能語・助詞・代名詞の対応のずれ。
- 訳語が完全一致しないだけのもの (辞書に「置く」とあり訳文が「載せた」など意味の範囲が重なっていれば可)。
- 活用や語形から出る意味 (時制・数・定不定など)。これは文法の領域なので判定しない。
- `japanese` が `null` の文。

判断に迷ったら `lookup.ts ja <日本語>` で「その意味の語が本当に別にあるのか」を確かめると精度が上がる。

## Step 5: 報告する
**最初の返答は、Step 4 の 2 つのサブセクションに当てはまる例文をただ列挙するだけにする**。
ユーザーから追加の指示があるまで、それ以外のことを書かない。

該当する例文の情報は箇条書きで示す。
この際、最初に原稿に書かれているフェンナ語文と日本語文 (複数ファイルを調査した場合はファイル名も) を示し、その後で問題点を簡潔に述べる。

書式の目安:
```
## 辞書にない語形
1. Бо̀ теҕду̂л ни̂рахха ши̂тики̂ҕҕажевот агре̂мевот. → 1.25 kg のミカンを買ってきてください。 (`document/ja/fennese/grammar/21.zml`)
   - ни̂рахха, агре̂мевот が辞書で引けません。
2. Есехлу̂фно фи̂срa ле и̂ццес. → 彼はボールを私の方に放り投げた。 (`document/ja/fennese/grammar/17.zml`)
   - фи̂срa にラテン文字が混ざっています (最後の a)。

## 訳文との食い違い
1. …… → …… (`document/ja/fennese/grammar/10.zml`)
   - 訳文の「川」に当たる語はありますが、「一緒に」に当たる語が見当たりません。
```

- 例文はフェンナ語文そのもので示す。行番号は出さない (原稿を見れば分かる)。
  対象が複数ファイルに跨がるときだけ、どのファイルかを添える。
- 単語に言及するときは、fennese-dictionary スキルの規則通りオンライン辞書へのリンクにする。
  ただし**引けなかった語形にはリンクを付けない** (見出し語が特定できていないため)。
- 最後に「何文を検査して何文に問題があったか」を 1 行で添える。
- 問題が無ければ「N 文を検査して問題は見つかりませんでした」とだけ言う。
- 文法については判定していないことを明記する。

最初の報告には**含めないもの**:
- 修正案・正しい綴りの候補
- 「これは誤検出と思われる」という自己判断による除外
- 引けなかった語形についての由来や妥当性の考察

ユーザーが「これはどう直せば良いか」「なぜ引けないのか調べて」と追加で指示したときに初めて、辞書データを掘り下げたり修正案を出したりする。
この際の辞書データの扱いについては、fennese-dictionary スキルの `SKILL.md` を必ず参照すること。

## ファイル構成
```
verify-fennese/
├── SKILL.md
└── scripts/
    ├── extract.ts   例文リスト (\xl, \xol) から文と訳文を抜き出す
    └── gloss.ts     抜き出した文の各語を fennese-dictionary で引いて 1 行にまとめる
```

## 注意
- `extract.ts` はこのリポジトリが変換に使っているのと同じ `@zenml/zenml` の `ZenmlParser` を `generator/generator.ts` と同じ設定 (`{brace: "x", bracket: "xn", slash: "i"}` と `plugin/` のマクロ) で呼んでいる。
  そのため **リポジトリのルートから実行すること** (`node_modules` と `plugin/` を参照する)。
- パースに失敗したファイルはその旨を標準エラーに出して読み飛ばす。
  原稿側の構文エラーの可能性がある。
- `\gloss` の中の `\li` は語単位の逐語訳なので、例文としては抽出されない (直下の子要素しか見ないため)。
- このスキルは原稿を書き換えない。
  修正はユーザーの指示を待つこと。
